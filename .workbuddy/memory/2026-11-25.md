## GM p358 车机（Android 6.0.1）有线连接适配

- 背景：用户的 GM 车机系统包（见 D:/a/GM_refreshpkg_p358/车机系统安装包分析报告.md）缺 `com.android.vpndialogs`（VPN 授权页），且无法用 ADB；OpenHC 的有线链路要靠 VpnService 建 TUN，授权页缺失时有线被直接判不可用。
- 机制验证（AOSP marshmallow-release 源码）：授权状态 = AppOps `OP_ACTIVATE_VPN`；系统框「确定」= `prepareVpn(null, pkg)` + `setVpnPackageAuthorization`；隐藏 API `VpnService.prepareAndAuthorize(Context)` 可免弹窗完成同样动作，服务端只查签名级 `CONTROL_VPN`。该车机系统整包用 AOSP 公开 testkey 签名，OpenHC 用同一把 testkey 签名即可拿到该权限。
- 实现：`VpnConsent.ensureAuthorized/isAuthorized/canShowPage/canSelfAuthorize` + `VpnConsentFlow`（纯逻辑决策表）+ `VpnPageMissing`；调用点（MainActivity、ConnectionController、SilentConnect 开机静默）改为 ensureAuthorized/isAuthorized；platform 清单声明 CONTROL_VPN 和 vpndialogs 可见性；诊断日志加「系统里有 VPN 授权页」「VPN 授权」两行。
- 顺手补完 0.2.8 WIP 缺口：DeviceCapabilities/DeviceCapabilitiesSection 的 `settings_device_*` 8 条字符串、设置页接入「这台车机」分组（SettingsScreen）。
- 构建：app/build.gradle.kts 新增可选 `openhc.platformSigning`（PKCS12）签名配置，配了它 debug/release 都用平台密钥签；`tools/platform-key/`（make-keystore.sh + README）负责把 AOSP testkey 转成密钥库、核对指纹（C8:A2:E9:BC:CF:59:7C:2F:B6:DC:66:BE:E2:93:FC:13:F2:FC:47:EC:77:BC:6B:2B:0D:52:C1:1F:51:19:2A:B8）。
- 限制：本机只有 JDK 11、无 Android SDK（项目要 JDK 17 + SDK 36），未能跑 `gradlew check`，改动经静态核查 + AOSP 源码比对；真机验证留待用户。
- 文档：docs/ANDROID6.md 更新自授权路径；README 常见问题加一条；CHANGELOG 记 0.2.8（开发中）。

- `./gradlew check assembleDebug` 首跑暴露三处问题，均已修复并全绿（323 tasks，BUILD SUCCESSFUL）：
  1. lint 报 CONTROL_VPN 是 ProtectedPermissions → manifest 加 tools:ignore（预期内，本方案就是给平台签名变体用的）；新反射调用加 @SuppressLint("PrivateApi")。

  3. 既有 bug：tools/desktop 的 PrivateFiles 按 POSIX（0700/0600）落盘，NTFS 无 posix 视图直接 UnsupportedOperationException。修复：posixSupported 探测（supportedFileAttributeViews），无 posix 时跳过权限设置/检查；对应测试加条件跳过（与项目既有 root-skip 风格一致）。
